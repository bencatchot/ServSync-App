# Job expenses: private capture and direct-cost review

**Status: hosted fictional review plus durable local validation, no hosted financial ledger.** The expense review entry contains synthetic identities and sample work, with data local to memory. Reloading clears it. It is built only for this feature branch's Vercel Previews (or served by local Vite). It makes no service calls, writes no browser storage, and adds no shipping app route. Never use real receipts or customer data in the preview. Role switching is a review control, **not authorization**.

## User decisions and scope

- Owner/Admin/Office should record private actual expenses against an estimate or its job. When a job originates from an estimate, display one ledger, not cloned expenses. Direct job expenses without an estimate still count, but have no invented revenue projection.
- A field technician should be able to enter an amount and submit a receipt, without access to profit, other employees' costs, receipt history, or manager correction. Manual capture does not require a photo. Receipt capture uses browser camera/file selection. Supports JPG or PNG only; on a device that supplies HEIC or an oversized file, choose a JPG/PNG copy or record the cost manually without the receipt. Physical camera integration is not verified; there is no OCR.
- Customers have no cost/receipt path, sharing toggle or billable-line action. These are never attachments to an estimate, invoice, report, homeowner library, Home History, guest view or customer PDF. Do not extend generic attachments or add selectable cost columns to customer-visible records.
- Distinguish actual direct cost from Price Book estimated cost. The example subtracts actual recorded direct cost from accepted pre-tax estimate revenue, not from invoice plus deposit or cash collected. It is a projection, not company net income; unknown quote yields no projection. Before adding billed/collected profit views, reconcile progress/deposit/final credits, discounts, voids and taxes.
- The review lets management correct an erroneous cost by excluding it from totals and entering its replacement. The real ledger should retain an internal audit trail of corrections. No production financial records are changed.

## Assigned jobs only; never required for management

The ordinary job is an inspection. Its existing write helper in `servsync-job-lifecycle.sql` checks contractor/team role, not an individual job assignment. Per Ben's decision, only a specifically assigned, active field technician can record expenses for that job. Job Details includes an optional manager control, next to the private expense tools. Solo owners and other management users can log expenses without enabling or touching assignments. The assignment grants expense submission only on scheduled, in-progress or completed jobs, not any other job/financial authority. Existing company-wide job permissions remain unchanged.

## Durable local review boundary

1. The review migration under `docs/migration-review` is not on any rollout manifest. It creates a non-exposed, forced-RLS schema for expense entries, receipt bytes and per-job assignments; there are no direct client grants. Small fixed-path RPCs derive the current contractor and role, deny anonymous and nonmembers, and return only the data authorized for that exact work item. Managers include that workspace's active owner/admin/office, not platform admins by default. Tech capture returns only the ability to submit, with no amounts, ledger, project profit or private receipt links. Assignment and team membership are checked for each submission and guarded against concurrent revocation.
2. Every expense has exactly one source estimate or source job. An accepted estimate and its job are combined into one view only when the two canonical links agree and both belong to the same contractor. One-sided or mismatched links cannot combine ledgers. Server pagination keeps totals across all pages; archived costs never affect totals or expose receipts. The scoped idempotency key prevents repeat submissions being counted twice. No estimate/inspection/invoice/PDF/customer DTO was amended to include internal details.
3. One optional photo saves atomically in a separate private table with the expense, eliminating public/signed links, orphaned uploads and separate bucket permissions. Cap: 3 MiB original, 4 MiB plus small JSON overhead in the Supabase RPC request. A server check rejects invalid size, unsupported media and wrong JPEG/PNG signatures. No photo name or bytes in normal list responses or client error telemetry; manager receipt read is an authenticated POST from the exact job/estimate scope and object URLs are released in the UI. Full image decode/metadata stripping and project-specific access-log configuration are unverified. Never use real receipts until log/no-cache behavior and image and HTTP limits are verified on an approved target.
4. The live app integration compiles only in dev mode with `VITE_SERVSYNC_DEV_JOB_EXPENSES=true` and a loopback HTTP Supabase endpoint. The Vercel build remains the approved independent synthetic memory-only review. The local SQL tests use a disposable socket-only PostgreSQL 16 process and do not read/write an existing Supabase or app database.
5. **Release gates:** verify on target schema and PostgREST, with disposable tenants and camera devices; approve private schema application and rollout separately. Establish receipt retention/deletion, redaction and backup/restore. Private entries restrict hard deletion of the source estimate/job/contractor in the draft model, preserving financial history; review expected draft deletion and account deletion behavior before enabling persistence. Help Studio freshness for real app onboarding must be checked at activation. No production merge, credentials, live DB or TestFlight change is authorized.

Official references: [Supabase storage access control](https://supabase.com/docs/guides/storage/security/access-control) and [Postgres row-level security](https://supabase.com/docs/guides/database/postgres/row-level-security). No bucket, existing auth/policy, live schema, or live access change was applied.
